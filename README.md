# Text-to-SQL 助理 (Text-to-SQL Agent)

這是一個基於 LangChain / LangGraph 架構開發的智慧型資料庫查詢助理。能夠將使用者的自然語言問題自動轉換為精準的 MySQL 查詢語句，並在驗證無誤後執行，最後將查詢結果整理成人類易讀的繁體中文回答。

## 整體架構與工作流程

本系統採用 **Tool-Calling Agent** 模式，讓大型語言模型 (LLM) 擁有自主探索與驗證資料庫的能力，而非單純的「盲寫 SQL」。

核心架構依賴以下 5 個專用工具（Tools），Agent 會依序或視情況動態呼叫：

1. **`list_all_tables` (問題分析與探索)**
   - Agent 第一步會呼叫此工具，獲取資料庫中所有的資料表名稱與中文註解，了解目前有哪些資料表可用。
2. **`get_table_schema` (結構與關聯解析)**
   - Agent 根據上一步的結果，查詢相關資料表（例如 `orders`, `customers`）的完整欄位結構、資料型態、主鍵 (PK) 與外鍵 (FK) 關聯。
3. **`get_sample_data` (資料格式確認)**
   - 若遇到不確定的資料格式（例如 `status` 欄位是存整數還是字串、時間格式長怎樣），Agent 會先調閱前 3 筆資料來確認。
4. **`validate_sql` (語法與安全性驗證)**
   - **核心防呆機制**。Agent 寫好 SQL 後，必須先呼叫此工具（底層使用 MySQL `EXPLAIN` 指令）來驗證語法是否正確。若有錯，Agent 會讀取錯誤訊息並自動重試修正（最多 3 次）。
5. **`execute_sql` (執行與總結)**
   - 語法驗證通過後，Agent 才會實際執行 `SELECT` 查詢獲取資料，並整理成繁體中文回答給使用者。
   - **安全限制**：嚴格限制只能執行唯讀的查詢，所有 `INSERT`, `UPDATE`, `DELETE`, `DROP` 等破壞性操作皆會被攔截阻擋。

## 支援查詢的資料與範例

系統預設內建一套「電子商務 (E-commerce)」虛擬資料庫（可透過 `python init_db.py` 自動生成與初始化），包含以下關聯式資料表：

- **`customers` (客戶資料)**：包含姓名、Email、電話與註冊時間。
- **`products` (商品資料)**：包含商品名稱、分類 (類別)、單價與目前庫存量。
- **`orders` (訂單紀錄)**：包含所屬客戶、訂購日期、訂單總金額與訂單狀態（例如 pending, completed）。
- **`order_items` (訂單明細)**：紀錄每筆訂單中購買了哪些商品、購買數量與結帳單價。

### 您可以向 Agent 詢問什麼？

只要是與上述四個資料表相關的業務邏輯，您都可以用自然的口吻提問。以下是一些經典的查詢情境與**預期回答範例**：

> 💡 **溫馨提示**：由於 `init_db.py` 每次產生的假資料都是**隨機生成**的（包含姓名、金額與訂單狀態），因此您實際查詢出來的結果數字與人名，會與下方的範例不盡相同喔！

**0. 基礎與一般查詢 (單表查詢)**
* **問：**「目前資料庫裡面總共有幾位客戶？」
  * **預期答：** 查詢結果顯示，目前資料庫中總共有 50 位客戶。
* **問：**「請告訴我『家電』分類中，單價超過 5000 元的商品有哪些？」
  * **預期答：** 家電分類中單價超過 5000 元的商品有：掃地機器人 (12,000元)、空氣清淨機 (8,000元)、除濕機 (6,000元)。

**1. 排名與統計分析 (多表 JOIN)**
* **問：**「請幫我找出所有居住在『台北市』的客戶中，累積消費總額（所有狀態為 COMPLETED 的訂單）最高的前三名是誰？他們各自花了多少錢？」
  * **預期答：** 根據查詢結果，居住在台北市的客戶中，累積消費總額最高的前三名是：1. 黃俊傑 (72,720元)、2. 張雅婷 (71,610元)、3. 劉美玲 (61,038元)。
* **問：**「在所有『已經出貨 (SHIPPED)』的訂單中，哪一個『商品分類 (category)』的總銷售數量最高？總共賣出了幾個？」
  * **預期答：** 在所有已出貨的訂單中，銷售數量最高的商品分類是「家電」，總共賣出了 37 個。

**2. 複雜條件與跨表關聯**
* **問：**「請幫我列出所有買過『MacBook Air』的客戶姓名、聯絡電話，以及他們下單的日期（只要列出最新的前 5 筆就好）。」
  * **預期答：** 以下是最近買過 MacBook Air 的前 5 筆客戶紀錄：1. 陳阿華 (0927646310, 2026-08-05)、2. 王俊傑 (0928881485, 2026-08-02)、3. 洪柏翰 (0911502688, 2026-07-30)、4. 李建國 (0975330564, 2026-07-17)、5. 黃俊傑 (0913733472, 2026-06-30)。
* **問：**「請幫我找出『至少有過 1 筆訂單被取消 (CANCELLED)』的客戶姓名，並列出他們各自取消了幾筆訂單？」
  * **預期答：** 查詢發現有 18 位客戶曾被取消訂單：張俊傑 (取消 2 筆)、郭家豪 (取消 2 筆)、陳家豪 (取消 2 筆)、劉家豪 (取消 1 筆)、劉心怡 (取消 1 筆)、吳淑芬 (取消 1 筆)、張雅婷 (取消 1 筆)、李宗憲 (取消 1 筆)、李建國 (取消 1 筆)、林宜蓁 (取消 1 筆)、楊建國 (取消 1 筆)、楊志強 (取消 1 筆)、王美玲 (取消 1 筆)、蔡佳穎 (取消 1 筆)、謝俊傑 (取消 1 筆)、謝宜蓁 (取消 1 筆)、謝志強 (取消 1 筆)、陳阿華 (取消 1 筆)。

**3. 進階彙整與子查詢 (Subquery)**
* **問：**「請先幫我計算出所有訂單的『平均消費金額』大約是多少？接著，在所有『高於平均值』的訂單中，金額最高的那一筆是哪位客戶買的？花了多少錢？」
  * **預期答：** 所有訂單的平均消費金額約為 20,178 元。其中金額最高的一筆訂單是由「謝志強」所購買，總花費為 113,650 元。

## 如何執行

1. **環境配置**：
   - 確保本機 MySQL 伺服器 (Port: 3306) 已啟動，且 `.env` 檔案中設定了正確的 `MYSQL_URI` 與 `GROQ_API_KEY` (或對應的 LLM API Key)。
2. **初始化假資料**：
   ```bash
   python init_db.py
   ```
3. **（選用）更新 README 範例答案**：
   每次重新執行 `init_db.py` 後，資料庫內容都會隨機重新生成，本 README 中的預期回答範例也會跟著失效。
   請執行以下腳本，自動查詢資料庫中的正確答案並更新 `answers.json`，再手動對照更新 README：
   ```bash
   python get_answers.py
   ```
4. **啟動對話終端**：
   ```bash
   python main.py
   ```
   啟動後，即可直接在提示符號 `>` 後方輸入您的問題與 Agent 進行互動！
